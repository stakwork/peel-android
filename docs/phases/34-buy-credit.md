# Phase 34 — Buying credit

Status: **step 7 of the org-page port: built, compiled and unit-tested; the sheet UI compiled only, nothing run on a device or emulator.** `buy_credit`, `buy_credit_status` and `buy_credit_cancel` (strut's specs/WALLET.md §1.2; iOS commit cfa9826b, PR #551) on a stranger's public page (the `Origin` scope); `host_capability` now lists all four ops there and none for an org.

## Built
- **`engine/CreditPurchase.kt`**: `CreditPurchase.problems` (a port of strut's `creditPurchaseProblems`, same words and order), `CreditPurchase.of`, `CreditReply.read` (strut's `readCreditReply`, as iOS's tests read the host's answer: `paid`/`pending`/`fallback`), `HostCapability.read` (the strut-side reading of a native host's capability: version 1 only, the four known ops, a name of at most 40 characters; null for anything else).
- **`WalletHost`**: `buy_credit` (visitor scopes only, else `RESTRICTED` "Peel buys credit only for a public app it opened itself."; `BAD_REQUEST` "Peel does not pay that: …"; the invoice decoded by Peel to the purchase's amount and hash, "The invoice is not the one the server describes."; not ended, "The invoice has ended."; `wallet.problem(paying:)`; the tap rule; its own sheet every time, named by the host Peel loaded; "You declined to buy the credit."; "The invoice ended while you were asked."; paid by a task of the host's own that a page's cancellation does not stop; kept under `credit:<scope key>`, so no budget counts it and no page is notified); a second `buy_credit` for a hash being paid or paid answers that payment with no sheet (`crediting`, then `records(connection:)`); `buy_credit_status` (`BAD_REQUEST` "payment_hash must be 64 hex", `NOT_FOUND` "Peel paid no such invoice for this page." for another page or an unknown hash); `buy_credit_cancel` (always `{}`; takes down this page's own sheet for that hash, a decline `USER_REJECTED` "The page stopped waiting, so Peel took its sheet down.").
- **Sheet withdrawal**: `askPerson(timeoutMs, withdrawnBy)`: a `CompletableDeferred` in `withdrawable` (key `<scope>|<hash>`) raced with the person's answer; the loser is cancelled, which takes the sheet down. The credit sheet's wait is the shorter of the invoice's end and the sheet timeout (`RESTRICTED` "You did not answer in time.").
- **`host_capability`**: ops `WalletHost.VISITOR_OPS` = `[buy_credit, buy_credit_status, buy_credit_cancel, sign_in]` for an origin, `[]` for an org. The #74 fall-through for `buy_credit*` is gone.
- **UI**: `WalletCreditSheet` + `WalletPerson.buyCredit`; `WalletSheet.Credit` (id `credit <host> <msat>`); `PhoneWalletSheets.buyCredit` (a cancelled coroutine takes the sheet down and frees the slot); `WalletWords.creditTitle/creditApp/creditBuys/creditNote`; `WalletPayStep(armedNote = …)` (credit's "Check the amount, then confirm."); `WalletCreditPhoneSheet` in `ui/page/WalletSheets.kt` (title, app line, big amount, "Runs …", "Buys …", "Fee added on top", "The server says: “…”", note, the touch-safe two-step, Decline).
- The engine never pays one hash twice: `EngineWallet.problem(paying:)` is `invoiceProblem` (pending, paid, own, expired: step 5, `AppPaymentsTest`); the credit host asks it before the sheet.

## Differences from iOS
- Only `Org`/`Origin` scopes: the Mac's `.remote` ("That is not the server this page shows." when the purchase's seller is not the page's) does not exist.
- `HostCapability.read` is written here from the vectors (iOS has no reader in Swift; its test only counts the list); the 40-character name limit is inferred from the vector ("a name too long to show").
- The vectors are looped in one test per list with the vector's name in each failure message, not a Parameterized runner (Robolectric supplies `org.json`).
- `buy_credit_cancel` answers `{}` for an org too (as iOS), though only a visitor can have a sheet up.
